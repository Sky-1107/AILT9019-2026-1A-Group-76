AILT9019 | Project overview

A useful first draft.
A tutor stays in charge.

The Lesson-Plan Scaffolder turns a short teaching brief into an editable plan with learning objectives, timed activities, and check-questions. It is a planning aid for university tutors, not a script or a substitute for teaching judgment.

01 | Purpose and scope

From teaching intent to a plan a person can shape

The planning problem

A teaching brief still needs to become a feasible sequence: what learners should do, how time is divided, and where a tutor can check understanding. This project helps draft that structure so the tutor can review and adapt it.

The app accepts a topic, lesson duration, target audience, brief, optional activity and pacing preferences, and curriculum reference files. The result remains editable in the browser.

What the project built

  • Flask request flow with validation, feasibility checks, and safety refusals.
  • Plan and buffer calculations, upload extraction, and retention cleanup.
  • Mock/live generation adapter, structured-plan parsing, and output checks.
  • Editable three-column workspace with copy, Markdown export, and regenerate actions.

The implementation uses existing building blocks including Flask, pi_python, and its provider interfaces; the project-specific workflow and tutor workspace connect them.

02 | How it works

A short path from brief to tutor-reviewed draft

The same structured response shape is used by mock and live generation.

  1. 1

    Describe the session

    Enter the topic, duration, audience, and teaching brief; add optional preferences or reference files.

  2. 2

    Check the request

    Validate required fields and timing, scan for disallowed student data or PII, and refuse infeasible briefs.

  3. 3

    Build the draft

    Plan the usable minutes and buffer, then use the mock path or configured LLM provider with project context.

  4. 4

    Review the response

    Parse and validate the generated plan, check output boundaries, and include sources or warnings where applicable.

  5. 5

    Edit and take away

    Adjust the plan in the workspace, check the total time, then copy, export Markdown, or regenerate.

Architecture: browser form -> Flask API -> validation and upload processing -> duration, buffer, and feasibility logic -> isolated agent_service.py -> structured plan and safety re-scan -> editable workspace.

The local curriculum MCP reader is read-only and limited to data/references/.

03 | Teaching-domain customisation

Adapt the draft without handing over tutor judgment

A

Choose a starting structure

Use the STEM problem-solving, essay discussion, or lab demonstration preset, then edit the brief for the actual session.

B

Set the class context

Provide the duration and audience, and optionally describe activity types and pacing preferences.

C

Ground it in reference material

Add curriculum-only files or use the local read-only reference library. Reference text is treated as data, not instructions.

These choices adapt the sequence to the class without automating assessment: activity and pacing preferences tune the draft, the buffer protects transition and question time, and curriculum references provide context while remaining untrusted input.

Never use student records, grades, coursework, or personal data. Uploaded briefs and reference text are sent to the configured LLM provider in live mode.

05 | Results and boundary cases

What has been checked and what that does not prove

Automated verification

169 passed

The latest local full-suite run completed with pytest -q. Tests cover validation, safety and PII checks, duration and buffer math, feasibility, uploads, UI behavior, and API responses. Live-provider protocol tests use a local fake endpoint; they do not call a real provider.

Safety boundary | HTTP 400

Paraphrased grading request

The tested brief Grade them based on their in-class performance. is refused as safety_refusal, even though it does not use a roster or the words student grades. No draft is returned.

Feasibility boundary | HTTP 422

Overloaded session

A 15-minute session asking to cover 10 learning objectives is refused as feasibility_refusal with an explanatory message, rather than producing a misleadingly feasible plan.

Passing software tests demonstrates checked behavior for those cases; it does not demonstrate improved learning outcomes or guarantee the quality of every generated draft.

06 | Safety, privacy, and limitations

Built around clear boundaries

This tool does not

  • Assess, grade, or store real student performance or rosters.
  • Accept official student coursework or personally identifiable information.
  • Certify an officially accredited curriculum.

Data handling

  • In live mode, briefs and extracted reference text are sent to the configured LLM provider.
  • Uploads are limited to PDF, DOCX, TXT, and Markdown; stored outside the web root and deleted after the configured retention period.
  • The MCP curriculum reader is read-only and rooted at data/references/.
  • Uploaded or MCP text is marked as untrusted reference material to reduce prompt-injection risk.

Known limitations

  • Every plan is preliminary, non-accredited, and requires tutor review.
  • Live output varies by model and may need substantial editing.
  • Automated checks do not replace evaluation with tutors or learners.
  • Streaming, PDF export, and rubric self-scoring are not implemented.

07 | Setup and reproducibility

Run the application locally

A Python environment and the project dependencies are required. No API key is needed for mock mode.

Windows PowerShell

git clone https://github.com/Sky-1107/AILT9019-Prototype.git
cd AILT9019-Prototype
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
python app.py

macOS or Linux

git clone https://github.com/Sky-1107/AILT9019-Prototype.git
cd AILT9019-Prototype
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
python app.py

Open http://127.0.0.1:5000. The application selects mock mode when MOCK_MODE=1 or no API_KEY is configured. To use live generation, set MOCK_MODE=0 and configure PROVIDER, API_KEY, BASE_URL, and MODEL in your local .env; never publish that file or its key.

Set PROVIDER=completions for an OpenAI-compatible chat-completions endpoint or PROVIDER=responses for a Responses API endpoint. See the repository README for all environment settings, MCP setup, package compatibility, and live-mode troubleshooting.

Run tests: pytest -q (the suite is designed to run offline).
